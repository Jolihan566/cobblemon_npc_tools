01🗂Overview & Datapack Structure

Cobblemon NPCs are defined by NPC Class files — JSON files inside a Minecraft datapack. Every NPC entity spawned in the world references one of these class files, which defines appearance, party, interaction behaviour, and AI configuration.

This builder produces a ready-to-install datapack ZIP. The correct folder layout for a 1.21.1 Cobblemon server is:

your_datapack/ ├── pack.mcmeta // Minecraft pack metadata (pack_format 48 for 1.21.1) └── data/ └── <namespace>/ // your chosen namespace, e.g. "myadventure" └── cobblemon/ ├── npcs/ // NPC class JSON files ├── behaviours/ // Brain AI behaviour files ├── dialogues/ // Dialogue JSON files ├── molang/ // MoLang script files └── callbacks/ // Callback script files
ℹ
Namespace: Must be lowercase with no spaces — e.g. myserver or my_adventure. It prefixes all resource identifiers like myserver:my_npc.
02🪪Identity & Hitbox

The Identity page sets the NPC's unique identifier, rendering override, preset references, hitbox, and entity flags.

namespace : nameidentifierrequired▶
The resource identifier for this NPC class, e.g. myadventure:professor_oak. The namespace is your pack/mod ID. The name is this specific NPC class. The file is saved as <name>.json in cobblemon/npcs/. Referenced in spawn commands: /cobblemon npc spawn myadventure:professor_oak.
resourceIdentifierstring▶
Optional override for the rendering identifier. Allows multiple NPC classes to share the same model/texture. Leave blank to default to the class identifier. Useful when you have e.g. 10 different trainer classes that all look like a Bug Catcher.
presetsstring[]▶
List of NPC Class Preset identifiers from the npc_presets/ folder. Preset properties are merged into this class on load. Properties defined directly here override the preset. Allows shared AI and config across many NPC types. Example: cobblemon:npc-standard.
hitboxobject | string▶
The NPC's collision and pathfinding volume. Use "player" (width 0.6, height 1.8 — the standard humanoid Steve hitbox) or a custom object {"width": 0.6, "height": 1.8} for non-humanoid sizes.
Default: "player"

03🎨Appearance & Variations

Variations generate aspects — named tags that the client rendering system uses to select textures and model parts. The variation keys are arbitrary names you define; their meaning depends on the model's resource pack configuration.

Uniform variationarray▶
A list of strings — one is chosen at equal random probability per spawn. Example: dirt: ["clean", "slightly_dirty", "dirty", "filthy"] gives each spawned NPC a 25% chance of each state.
Weighted variationweighted▶
Each option has an aspect name and a weight. Probability = weight / total_weight. Weights 10, 5, 1 → 62.5%, 31.25%, 6.25%. Multiple variation keys are independent and stack — a NPC can simultaneously have clean + green-net, or dirty + red-net.
💡
In pool parties, MoLang expressions can reference aspects: "weight": "q.npc.has_aspect('dirty') ? -1 : 0" guarantees a Pokémon only for dirty variants.
04📝Names
namesstring[]▶
One name is chosen randomly when the NPC spawns. Can be plain strings like "Red" or translation keys like cobblemon.npc.name.red for localisation. Single-entry list = consistent name. Accessible in MoLang/dialogue as c.npc.name.
05💬Interaction

What happens when a player right-clicks this NPC. Four types:

nonetype▶
The NPC ignores right-clicks. Use for purely decorative NPCs or when interaction is handled via behaviours.
dialoguetype▶
Triggers a dialogue JSON file from dialogues/. Specify its resource identifier e.g. myadventure:ranger_alex_greeting. The dialogue receives c.npc as context, enabling c.npc.config.my_var access inside dialogue scripts. Create dialogue files in the Dialogue Editor tab.
scripttype▶
Runs a MoLang script file from scripts/ on right-click. Context: c.npc, c.player. Specify the resource identifier e.g. myadventure:give_starter.
custom_scripttype▶
MoLang written inline in the NPC class. Good for short one-off logic. Multi-line is stored as a JSON array. Context: c.npc, c.player. Example: c.player.tell('My name is ' + c.npc.name);
06⚔Battle & Skill
battleConfiguration.canChallengeboolean▶
Whether players can initiate a Pokémon battle. Set false for non-trainer NPCs like shopkeepers.
Default: true
skill1 – 5▶
Battle AI difficulty. Does not affect Pokémon stats — only how intelligently the NPC plays. 1 = random decisions, 5 = optimal play. Party quality (levels, moves, EVs) is independent and set in the Party section.
Default: 1
autoHealPartyboolean▶
Pokémon are healed to full between battles. When false, HP/PP persist and the NPC must find a healing machine (if that behaviour is configured). No effect on dynamic parties.
Default: true
randomizePartyOrderboolean▶
Sends a random Pokémon from the party first, rather than always leading with slot 1. Adds variety to repeated encounters.
Default: false
07🔴Party Types
⚠
Dynamic parties (isStatic: false) are generated fresh each battle. They disable: autoHealParty, persistent HP, and Pokémon out of balls.
simpleparty type▶
Fixed list of up to 6 Pokémon as property strings. Format: pikachu level=25 nature=timid moves=thunderbolt,iron_tail held_item=cobblemon:choice_specs shiny. Omit level to use the seed level (average player party level when spawned via world system, or the value from a spawn command). Static = generated once on spawn; dynamic = regenerated each battle.
poolparty type▶
Randomised party drawn from a weighted pool. Set minPokemon / maxPokemon to control party size. Each entry has: pokemon (property string), weight (probability, supports MoLang), npcLevels (seed level eligibility range e.g. "1-10"), levelVariation (±range), selectableTimes (max appearances), and optional level (MoLang expression for forced level). Use q.npc.has_aspect('dirty') in weights to give variant-specific Pokémon.
scriptparty type▶
Party built by a MoLang script in molang/. Available: q.party (builder), q.level (seed level), q.npc, q.players. Example: q.party.add_by_properties('pikachu level=' + (q.level + 3));. Most flexible — supports conditional logic and player-based scaling.

08⚙Config Variables

Named MoLang variables pre-declared on the NPC class, exposed to admins in the NPC Edit command. Allow a class to be data-driven without hardcoding — e.g. a preset with challenge range logic reads from a challenge_distance variable that the class declares with a sensible default.

variableNamestring▶
The MoLang variable name — snake_case, no spaces. Accessible in scripts as q.npc.config.challenge_distance or v.challenge_distance within attached scripts.
typeSTRING / NUMBER / BOOLEAN▶
Determines the in-game editor input type. NUMBER → numeric spinner. BOOLEAN → toggle. STRING → text field.
defaultValueMoLang string▶
The initial value as a string set on NPC initialisation. Can be a literal ("5", "true") or a MoLang expression.
09🧠Behaviour Files & Brain AI

Cobblemon uses Minecraft's Brain AI system. A Brain has activities (named modes like idle, fight, chatting) and each activity has tasks that execute each tick. Behaviour files live in behaviours/ and are referenced by the NPC class's behaviours array (auto-populated by this builder).

ℹ
Behaviour files you create here are automatically added to the NPC class's behaviours array and included in the datapack export.
add_tasks_to_activityconfig type▶
Adds tasks to an activity. Choose the activity then define priority groups. Lower priority numbers run first. Within a group, tasks run in order. Can be a simple string "cobblemon:wander_around" or a full object {"type":"cobblemon:go_to_healing_machine"}. If a task sets a walk target, place target-setting tasks at a higher priority number than tasks that consume the target.
scriptconfig type▶
Runs a MoLang script that modifies the brain or entity. q.entity = the NPC. Toggle Execute Early to run during the variable phase (before tasks are added) — needed when scripts decide which tasks get registered.
set_core_activitiesconfig type▶
Activities that always run in parallel regardless of the current default activity. Core is for fundamentals: floating in water, look targets. Default: ["minecraft:core"]. Add cobblemon:battling for battle-related core tasks.
set_default_activityconfig type▶
The fallback activity when nothing else is scheduled. Default: minecraft:idle. Wandering, challenge detection, and healing typically live in idle.
apply_behavioursconfig type▶
Applies other behaviour files by resource identifier — the composition mechanism. A shared cobblemon:uses_healing_machine behaviour can be referenced by any trainer NPC. Supports an optional MoLang condition (with q.entity) to gate application.
add_variables / set_variablesconfig type▶
add_variables declares MoLang variables at the behaviour layer with defaults and UI labels. set_variables forces specific values onto pre-existing variables — useful for locking preset variables to class-specific values.
ActivityPurpose
cobblemon:battlingActive during a Pokémon battle
cobblemon:action_effectPerforming an action effect — suppresses other tasks
cobblemon:npc_chattingIn dialogue — NPC looks at player, does nothing else
minecraft:idleDefault: wandering, challenge detection, healing
minecraft:coreAlways-on: floating, look targets
minecraft:fightEngaging in combat
minecraft:panicFleeing from an attacker
10🗨Dialogue Editor

The Dialogue Editor tab contains a full node-based visual editor. Each tab in the editor is a separate .json file exported to dialogues/.

ConceptDescription
Page (node)One screen of dialogue. Has a speaker, lines of text, and an input type.
Init BlockEntry point. MoLang conditions route to the starting page. Drag to reposition.
Input: optionsPlayer chooses from labelled buttons. Each option has an action list.
Input: auto-continueAdvances automatically after a configurable delay.
Input: textFree-text player response field.
q.dialogue.set_page('id')MoLang call to navigate to another page.
q.dialogue.close()Ends the dialogue.
WiresDrag a port dot (right side of node) to another node's socket to create a visual connection.
Expand nodeRight-click → Expand Node to see full content inline on canvas.
Flag SimulatorSidebar toggle: set q.player.data flags to preview which init action fires.
⚠
Remember to collect: click 📋 Collect for Datapack Export in the Dialogue Editor tab before downloading. Without this, dialogue files will not be included in the ZIP.

12🚀First NPC Walkthrough — Ranger Alex

This walkthrough creates a complete trainer NPC called Ranger Alex who greets players with a short dialogue before challenging them to a battle.

1
Set up Identity
Go to Identity. Set Namespace to myserver and Name to ranger_alex. Leave hitbox as player. Toggle Can Despawn off so Alex persists in the world. Toggle Is Invulnerable on so players can't accidentally harm him.
💡 The full identifier myserver:ranger_alex is used in the spawn command: /cobblemon npc spawn myserver:ranger_alex
→ Identity tab
2
Give him a name
Go to Names. Type Ranger Alex and press Enter. This floats above his head and is accessible in dialogue scripts as c.npc.name.
→ Names tab
3
Link his interaction to a dialogue
Go to Interaction. Choose Dialogue type. In the identifier field enter myserver:ranger_alex_greeting — this is the name you'll give the dialogue file in step 6.
→ Interaction tab
4
Configure battle settings
Go to Battle. Confirm Can Challenge is on. Set Skill to 3 for moderate difficulty. Leave Auto Heal Party on.
→ Battle tab
5
Build his party
Go to Party. Keep Simple type with Static on. Click + Add Pokémon twice and enter:

arcanine level=35 nature=adamant moves=flare_blitz,extreme_speed,crunch,wild_charge held_item=cobblemon:choice_band

dragonite level=37 nature=jolly moves=outrage,earthquake,fire_punch,aqua_tail
💡 To make Alex scale with player level, switch Static off and remove the level properties — seed level will be used instead.
→ Party tab
6
Build the greeting dialogue
Go to the Dialogue Editor tab. Click ＋ New in the editor toolbar and rename the tab to ranger_alex_greeting (double-click the tab name).

Right-click the canvas → New NPC Page. Set ID to greeting, add the line: "Hold it! I'm Ranger Alex — let's see what you've got!" Set Input to Options, add option label "I accept your challenge!" with action q.dialogue.set_page('accept');.

Add a second Player Page, ID accept, line "Let's go!", simple action input q.dialogue.close();.

In the Init Block, click ✎ and add an init action pointing to greeting. Wire the greeting node's port to the accept node's socket by dragging the coloured dot.

Finally, click 📋 Collect for Datapack Export.
→ Dialogue Editor tab
7
Export the datapack
Click 📦 Export Datapack. Set namespace to myserver, pack format to 48 (Minecraft 1.21.1), and give it a description. Download the ZIP, unzip it, and place the folder in world/datapacks/. Run /reload, then:
// Spawn Ranger Alex at your current position /cobblemon npc spawn myserver:ranger_alex
🎉 Ranger Alex is now live! Right-clicking him opens the greeting dialogue, and he can battle players via the challenge system.
→ Open Export
